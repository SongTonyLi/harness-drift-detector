# Agent Note: No tool attribution in commit messages or PR bodies

Status: implemented

## Problem

Coding assistants append attribution trailers and "generated with" lines to commit messages and pull request bodies by default. The maintainer wants git history to describe changes and reasons only, with authorship carried by the committer identity, and wants the rule enforced rather than remembered.

## Decision

Commit messages and PR bodies carry no tool attribution: no `Co-Authored-By` trailer naming an assistant, no "generated with" or "generated by" line, no robot emoji, no assistant product names, no assistant no-reply addresses. `scripts/verify_commit_message.py` rejects offending messages in the lefthook `commit-msg` hook and, in CI, over every commit in a pull request range. Human co-author trailers remain allowed.

## Alternatives considered

**Prose rule in AGENTS.md only.** Assistants follow enforced gates far more reliably than prose; a default trailer would return with the next tool update.

**Reject every `Co-Authored-By` trailer.** Simpler pattern, but it would block legitimate human co-authorship.

**Rewrite history after the fact.** Rewrites are disruptive on a shared branch and the message is already public once pushed.

## Consequences

History reads uniformly and attribution follows the committer. The pattern list needs a small update when a new tool name appears. A contributor whose tooling injects a trailer sees the rejection at commit time with the reason.
